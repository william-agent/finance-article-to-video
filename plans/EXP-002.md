# EXP-002 v2：ComfyUI 作為 Generative Asset Factory（GAF）的合約驗證

- **狀態**：規劃中（v2 對齊 2026-08-16，使用者主導收斂）。**未執行。**
- **v1→v2 的差異**：v1 問「VGM 品質如何、選哪家」；v2 把問題上移一層——**驗證 ComfyUI 能否成為固定的生成工作流層**，用固定外層 contract 穩定切換不同旗艦模型／供應商，產出可比較、可追蹤、可交給 Editor Agent 的素材。API-first 不變；替身影片取消，改用真 provider；不用 Lite/Flash，直上旗艦 tier。
- **鐵律**（沿用）：付費／credential／商用授權 → 先停下確認。每個 Agent／模型／工具／成本／授權／責任都記錄。

## 核心假設（H2）

> ComfyUI 定位為 **Generative Asset Factory**：上游收固定 **ShotSpec**，內部以 provider adapter 呼叫旗艦模型，
> 下游交出「可比較、可追蹤、帶完整 provenance」的候選鏡頭。
> 若同一份 ShotSpec 能在 ≥2 個真實 provider 上跑通且輸出可被 Editor Agent 選用，則 GAF 合約成立。

## 關鍵事實（preflight 已查證，2026-08-16）

**ComfyUI 官方 API Nodes** 讓這台無 GPU 的機器可以跑 ComfyUI 當純編排層——生成在雲端發生：
- 官方 partner nodes 覆蓋 Kling 3.0、Google Veo、OpenAI、RunwayML、MiniMax、Pika 等 62+ 節點，含 ElevenLabs 音訊
- 計費：向 ComfyUI 買統一 credits，跨供應商通用（credits/sec × duration）——**一個帳號、一個錢包，天然就是我們要的 adapter 抽象**
- 本地 ComfyUI 只做工作流編排，CPU 即可
- 來源：[ComfyUI partner-nodes pricing](https://docs.comfy.org/tutorials/partner-nodes/pricing)、[API nodes 教學](https://stable-diffusion-art.com/comfyui-api/)、[62+ API nodes](https://comfyui.org/en/comfy-gets-major-boost-with-new-api-nodes)
- ⚠️ 未驗證：Comfy credits 的實際單價 vs 直連 API 的價差——**買 credits 前先在購買頁核對**

## 實驗設計

### 固定 ShotSpec（合約的上游面）

`shotspec.schema.json`，每支鏡頭一份，欄位：
`shot_id`、`intent`（敘事目的）、`duration_sec`、`aspect`、`style_refs`、`reference_images`、`motion_notes`、`negative_constraints`、`acceptance_criteria`（可判定的驗收條款）、`facts_constraints`。

**財經硬規則**：VGM 畫面**不得要求出現任何數字或文字**（生成文字不可靠——EXP-001 已確立數字一律走 HyperFrames overlay 層）。

### 兩個真實 provider adapter（合約的內部面）

建議配對（都有官方 ComfyUI API node，一個 credits 帳號全包）：

| Adapter | 模型 | 旗艦 tier 價（直連行情參考） | 選它的理由 |
|---|---|---|---|
| A | **Kling 3.0** | ~$0.09–0.14/sec | 性價比口碑最好，動作自然度強 |
| B | **Veo 3.1 Standard**（非 Lite） | ~$0.40–0.75/sec | 品質天花板參照組，lip-sync 最佳 |

同一份 ShotSpec → 兩個 adapter 各生成（每 provider 每鏡頭 2 seeds）→ 候選池。

### 每次輸出的 provenance（合約的下游面）

`ledger.json` 逐筆：`provider`、`model/version`、`prompt`（adapter 實際送出的）、`reference`、`seed`、`cost`（credits＋折台幣）、`latency`、`output sha256`。

### Editor Agent（獨立歸責）

- 用 Claude 系 subagent（避開 Codex 權限審批問題），輸入：ShotSpec＋候選池＋storyboard 上下文
- 輸出：**EDL JSON**——每支候選 keep/reject＋理由；選中鏡頭的入點出點；歸責標識
- Editor 的判定與 conductor 的抽幀目檢分開記錄（兩雙眼睛，避免 EXP-001 的「決策散落對話」問題）

### Deterministic Finishing

選中鏡頭 → HyperFrames 組合（video 背景＋數字 overlay＋字幕）→ 兩次渲染 SHA256 驗確定性（EXP-001 機制沿用）。

### 評估指標

**每個可接受鏡頭的成本**＝總花費 ÷ 通過 acceptance_criteria 的鏡頭數（不是標價每秒）。
同時記錄：latency、重試率、adapter 切換是否零改 ShotSpec。

## PASS/FAIL

- **P1 合約成立**：同一份 ShotSpec 在兩個 adapter 跑通，零修改切換 → PASS
- **P2 可追蹤**：ledger 能回答每支候選的「誰、什麼、多少錢、多久、hash」 → PASS
- **P3 可選用**：Editor Agent 從候選池選出 ≥1 支通過 acceptance_criteria 的鏡頭 → PASS
- **P4 可合成**：選中鏡頭進 HyperFrames，確定性重現 → PASS
- **P5 成本可知**：算出 cost-per-acceptable-shot，含重試 → PASS
- 任一 FAIL 記錄根因，不連坐其他項

## 預算與 Blockers

- 量級：2 providers × 2 shots × 2 seeds ≈ 8 支 10 秒候選。以直連行情估：Kling ~$4–6、Veo Standard ~$16–30 → **建議預算上限 US$40**（Comfy credits 單價可能不同，購買頁見真章，超出先停）
- **Blocker 1**：ComfyUI 帳號＋credits 購買——需要你操作＋核可金額
- **Blocker 2**：credits 實際單價未驗證（見上）
- **Blocker 3**：edge-tts 商用仍 BLOCKED；本實驗聲音沿用 EXP-001 音檔（語音表演升級移到 EXP-002b 盲測，不混入本實驗變因）

## 排序

1. 【零付費】本機裝 ComfyUI（CPU 編排模式）＋寫 shotspec.schema.json＋EDL schema＋兩條 adapter workflow JSON 骨架，dry-run 到「差 credits 就能發射」
2. 【停】你開 Comfy 帳號、核可預算、確認 credits 單價
3. 生成 → ledger → Editor Agent 選鏡 → finishing → G3 手機驗收 → 算 cost-per-acceptable-shot
